# BC-GTSH



Official reproducibility code for **BC-GTSH: Bi-view Continual
Graph-Transferred Semantic Hashing**. The implementation addresses continual
cross-modal hashing when the image and text training streams are source-disjoint
and previously committed gallery codes cannot be rewritten.

The released objective is

$$
\mathcal{L}=\lambda_{\mathrm{top}}\mathcal{L}_{\mathrm{RowKL}}
+\lambda_{\mathrm{quant}}\mathcal{L}_{\mathrm{quant}}
+\lambda_{\mathrm{bit}}\mathcal{L}_{\mathrm{bit}}.
$$

Training labels provide privileged semantic topology. Inference uses only the
modality encoder and the shared hash layer.

## Installation

Python 3.10 and a recent PyTorch 2.x installation are required.

```bash
conda env create -f environment.yml
conda activate bc-gtsh
python -m pip install -e ".[dev,plot]"
```

The reference environment used PyTorch 2.6 with CUDA 12.4. CPU execution is
supported for tests and toy examples; formal experiments require a CUDA GPU.

## Quick smoke test

```bash
bc-gtsh make-toy-data
bc-gtsh smoke --device cpu
```

The toy data are generated deterministically and are not used for paper results.

## Data

The training feature files used in the experiments are publicly available from
[Baidu Cloud](https://pan.baidu.com/s/1BfMpHnTU3Dd3sU_XVA0lbg?pwd=1234) (Passwd: `1234`)


After downloading, place the feature files under data/ using the following
directory structure:

data/
|-- mscoco/MSCOCO_CLIP_image_CLIP_text_sonclass.mat
|-- nuswide81/NUSwide_CLIP_image_CLIP_text.mat
`-- iapr/IAPR_CLIP_image_CLIP_text.mat

Each HDF5/MAT file must contain Images, Texts, Labels, and Idx. Samples
are stored along axis 1 in the released feature files. Exact hashes and field
semantics are documented in docs/DATA.md.

Audit the data and frozen protocol before training:

bc-gtsh data audit --dataset mscoco --data-root data
bc-gtsh protocol verify --dataset mscoco --split test --data-root data

## Experiments

Run the frozen four-bit, three-seed Full matrix for one dataset:

```bash
bc-gtsh run --dataset mscoco --bits 16 32 64 128 \
  --seeds 2096 6513 9231 --device cuda:0 --resume
```

Run a structural ablation or control:

```bash
bc-gtsh ablate --dataset mscoco --condition no-cross --device cuda:0 --resume
bc-gtsh control --dataset mscoco --kind static-s1 --device cuda:0 --resume
bc-gtsh control --dataset mscoco --kind pairblind --device cuda:0 --resume
```

Use `--dry-run` to inspect a matrix without reading data. `--retry-failed` permits
a failed configuration to be attempted again, and `--fail-fast` stops a matrix
at the first failure.

Aggregate completed runs:

```bash
bc-gtsh aggregate --result-root results
```

Dataset-specific settings are frozen as follows:

| Dataset | Batch | Epochs/stage | LR | Intra/Cross k | Teacher temperature |
|---|---:|---:|---:|---:|---:|
| MSCOCO | 256 | 30 | 0.001 | 5/5 | 0.1 |
| NUS-WIDE-81 | 256 | 30 | 0.001 | 5/5 | 0.1 |
| IAPR | 128 | 90 | 0.002 | 20/20 | 0.2 |

See `docs/REPRODUCIBILITY.md` for the complete matrices and expected run counts.

## Evidence and paper assets

`evidence/` contains path-sanitized aggregates, diagnostic curves, and a
342-row per-run manifest derived from the frozen experiment records. It is not
presented as output freshly generated by the cleaned release implementation.
`evidence/runs.csv` retains metrics plus protocol, configuration,
source-artifact, and canonical row hashes without local paths;
`evidence/manifest.json` records the release transformation and parity checks.

```bash
bc-gtsh paper-assets --evidence-root evidence --output-root paper-assets
```

This generates LaTeX tables, continual curves, retrieval curves, and parameter
sensitivity plots. Qualitative retrieval cases additionally require the original
MSCOCO images and captions and are skipped when that media is unavailable.

## Evaluation tracks

- **Strict source-disjoint online:** BC-GTSH and UIH; no training source ID is
  shared between image and text streams.
- **Offline final-data references:** AMSH, GSPH, and EDMH observe the complete
  final training union and are reported separately.
- **Paired-source Oracle:** paired online methods and BC-GTSH-PairBlind receive a
  paired source pool. PairBlind independently permutes modality order and does
  not consume correspondence indices, but it is not a strict source-disjoint run.

The tracks must not be combined into a single fairness ranking.
